# えごさリサーチ（ドラフト v2・2026-11-09）

調べ物をAIに頼む習慣そのものに、英語を寄生させるためのスキルです。
利用者は日本語で聞いて「えごさ形式で出して」と言うだけでよく、追加の操作は要りません。

## 出力形式（えごさ形式）

- 出力は**単体のHTMLファイル**とし、同梱の `template.html` のデザイン（えごさ本体と同じ見た目・CSS・下部バー）を使う
- **見える面は全部英語にする**（店主指定）。タイトル、見出し、結論、本文はすべて英語で書く。日本語は最初から見える場所には置かない
- **ふりがな（ルビ）は難しい単語だけ**に付ける。対象は学習者の語彙を超える語・専門用語・イディオムに絞り、付けすぎない。ルビは日本語の短い意味
- **日本語はタップで初めて出す**。テンプレートの GLOSS データに単語と日本語訳を入れておき、タップしたときだけ下部バーに訳が出る。タップ対象は本文の単語全般で、ルビの無い単語にも訳を用意する
- **訳は3階層＋自由選択で用意する**（2026-11-09 本人要望で追加）:
  1. **単語**: GLOSS。タップで下部バーに訳
  2. **句・イディオム**: PHRASES に登録した複数語（句動詞・イディオム・決まった言い回し）は1つの単位として点線の下線を付け、単語より先に（長いもの優先で）マッチさせる。タップで句全体の意味が出る
  3. **文**: 本文の各文を `<span class="s" data-jp="文の日本語訳">` で囲む。単語でない場所をタップすると、文全体の訳が下部バーに出る
  4. **自由選択**: 利用者が任意の範囲を選択すると、その場で翻訳して出す（オンライン時のみ。テンプレートに実装済み）。事前に登録していない範囲はこれで受ける
- 構成は次の順:
  1. **Question**: 問いを英語で置く（利用者の日本語の質問は英訳する）
  2. **Conclusion**: 結論を英語で先に示す。平易な英語で書く
  3. **本文**: 英語で書く。決め手になる原文は引用としてそのまま残す
  4. **Sources**: 出典をリンクで全て示す。出典のタイトルが日本語の場合はそのまま併記してよい
  5. **Read the original**: 一番の一次ソースを1件挙げ、えごさ本体（ https://mozk-umino.github.io/egosa/ ）に貼れば読める形でURLをそのまま書く
- チャット本文には、結論の要約（こちらは日本語でよい）とHTMLへのリンクだけを短く返す

## 進め方

1. **英語で調べる**
   - 利用者の質問を英語の検索クエリに直し、英語の情報を優先して調べます。
   - 情報源は一次情報を優先します（公式ドキュメント、公式発表、論文、規格、当事者の発信）。
   - 英語の一次情報が無いテーマでは、無理に英語に寄せず、その旨を一言添えて通常どおり調べます。

2. **英語で書く。日本語は隠す**
   - HTMLの見える面（タイトル・見出し・結論・本文）は全部英語です。英語は平易に保ち、難しい言い回しは避けます。
   - 日本語訳を（ ）で添える書き方はしません。日本語は GLOSS データの中だけに置き、タップで初めて出します。
   - ルビを付けるのは難しい単語だけです。簡単な単語にまで付けると、英語を読む面が日本語だらけになります。
   - 決め手になる原文は引用して構いません。それ以外も含め、出典へ誘導する構成は保ちます。

3. **Sources と Read the original を付ける**
   - 使った情報源はすべてリンクで示します。
   - 最後に、一番の一次ソースを1件だけ「Read the original」として挙げます。
   - 原文リンクは、えごさ（ https://mozk-umino.github.io/egosa/ ）にURLを貼ればふりがな付きで読める形で、そのままのURLを渡します。

## やらないこと

- 見える場所に日本語を書かない（タップで出る GLOSS の中だけ）。日本語の説明文で英語を「解説」しない
- 学習指導や説教をしない。「勉強になりますよ」のような添えもしない
- 出典の無い断定をしない。英語で調べたことと、日本語の情報で補ったことを混ぜない
- 利用者が急いでいる様子のときは、えごさ形式にせず通常の短い回答を優先する

## 狙い（利用者向けの説明に使う一文）

聞く相手がAIでも、情報の入り口が英語なら、調べ物のたびに少しだけ英語に触れることになります。
